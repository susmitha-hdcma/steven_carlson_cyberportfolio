Case Study 01  /  Healthcare Operations × AI

CADMedic.AI

Founder · Architect · Engineer cadmedic.ai ↗

The problem

Private EMS agencies that run interfacility transport live inside a mess of disconnected software: one system for dispatch, another for patient charting, another for billing, spreadsheets for fleet and scheduling, and paper logs for controlled medications. Every seam between those tools is a place where data gets re-keyed, revenue leaks, and compliance risk hides.

I know this problem first-hand — I work as an advanced scope practice paramedic doing specialty-care transport. CADMedic.AI is the platform I wished my industry had, built by someone who has been on both sides of the radio.

What I built

One transport record from request to revenue. Eight interlocking modules on a single data model:

  • Dispatch / CAD — real-time command center with live unit tracking, call queues, and status visibility.
  • ePCR — structured field charting and documentation from crews.
  • Billing & revenue cycle — charges and coding flow directly from completed charts.
  • Fleet management — vehicle readiness, maintenance tracking, GPS integration.
  • Inventory & controlled medications — stocking, sealed kits, and medication chain of custody.
  • Workforce management — scheduling, timekeeping, credentialing.
  • RequestHub — a secure portal for healthcare facilities to submit and track transport requests.
  • Field App — a native iOS app for crew assignment and offline-capable charting.

The AI layer

  • Generative AI chart review — surfaces documentation gaps and quality issues before charts reach billing.
  • Narrative-driven revenue capture — analyzes crew narratives to find legitimately billable elements that manual coding misses.
  • Predictive availability forecasting — statistical learning applied to unit availability.
  • Constraint-based optimization — route and unit assignment under real-world operational constraints.

Security & compliance by design

This platform touches PHI at every layer, so the security model came first, not last: HIPAA-aligned architecture, role-based access control, auditable records throughout the transport lifecycle, and chain-of-custody handling for controlled substances. This is the same discipline I applied for 15 years as an acting CISO — now embedded in a product from its first commit.

What this demonstrates

  • AI engineering — generative AI, predictive analytics, and optimization deployed for operational outcomes, not demos.
  • Security architecture — HIPAA-by-design in a system that handles PHI, payments, and controlled substances.
  • Full-stack + mobile development — web platform, native iOS app, offline sync, GPS telemetry.
  • CI/CD & delivery — automated build, test, and release pipelines sustaining a multi-module product as a solo engineer.
  • Project management & domain authority — eight modules roadmapped and shipped coherently, informed by daily frontline experience.
Case Study 02  /  AI Agent Governance × DevSecOps

WaymarkHQ

Founder · Architect · Engineer waymarkhq.com ↗

The problem

AI coding agents are getting faster. Production is not getting safer. Teams adopting agentic development hand increasingly privileged access — credentials, deploy rights, production commands — to autonomous software whose behavior they can't fully predict. The industry's answer has been "more agents." The correct answer is a trusted boundary between agent intent and privileged action.

What I built

  • Studio — a native macOS control plane for orchestrating agent work: issues, agent runs, checks, approvals, and releases in one operational view. Every agent run executes in an isolated git worktree, with built-in recovery ("RepoSeatbelt") when things go wrong.
  • Broker — the security core. Credentials and privileged commands live outside agent reach; policy is enforced before execution; every privileged action leaves a durable evidence trail suitable for compliance review.
  • Multi-agent support — concurrent agents without shared privileged access, policy-driven automation with human approval checkpoints where they matter.

Why this is a security product

Waymark is CISSP doctrine translated to the newest attack surface in software. Least privilege: agents never hold credentials. Separation of duties: intent and execution are different systems. Complete mediation: policy checks every privileged action. Auditability: evidence is preserved per change, not reconstructed after an incident. Very few people hold both the security credentials to frame this problem and the engineering ability to ship the answer.

What this demonstrates

  • AI security leadership — original thinking on agent governance, the emerging risk domain every CISO will own within two years.
  • CI/CD governance — approval gates, release checks, isolated workspaces, and recovery patterns across multi-repo delivery.
  • Systems engineering — native macOS development, git infrastructure, MCP (Model Context Protocol) tooling.
  • Product strategy — a coherent architecture (Studio → Broker → Forge) aimed at a gap the market is only beginning to name.
Case Study 03  /  Computer Vision × Security  /  Acquired 2020

Cyberbully Watch

Founder · Architect Acquired by a Larger Technology Firm — 2020

The problem

Online-safety investigations need evidence that stands up: content gathered at scale, analyzed accurately, and handled so that every artifact remains admissible. Generic scraping tools can find material; they can't preserve forensic integrity while doing it.

What I built

  • End-to-end architecture — founded and architected a cloud-native security platform from initial concept through production deployment: core architecture, data pipelines, security controls, and operational workflows.
  • Data engineering at scale — high-throughput data ingestion, crawling, and processing pipelines in Python and Perl, optimized for scale, accuracy, and forensic integrity.
  • Computer vision / ML — image-matching workflows capable of large-scale analysis while preserving evidentiary chain-of-custody requirements.
  • Security engineering — cryptographically verifiable logging, tamper-resistant audit trails, and role-based access controls suitable for investigative and legal review, with VPN-based access and segmented network architecture for law-enforcement workflows.
  • Stakeholder collaboration — worked directly with investigators and legal stakeholders so system outputs met evidentiary, privacy, and admissibility standards.

The outcome

The business was sold to a larger technology firm — one of three businesses I've founded, built, and sold. I led the transition through acquisition, supporting knowledge transfer and operational handoff post-sale.

What this demonstrates

  • AI before the hype — production computer vision and ML shipped in 2018, not a post-ChatGPT pivot.
  • Security-grade engineering — forensic integrity, verifiable logging, and chain of custody as first-class requirements.
  • Founder-to-sale execution — concept, architecture, production, acquisition, and clean handoff.
